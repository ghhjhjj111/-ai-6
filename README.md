摘要
AI写作工具正在从封闭的SaaS服务向开源可自部署的方向快速演进。“一键写作生成器”的产品逻辑以极简交互降低了内容生产的操作门槛，而开源与独立部署则回应了用户对数据主权和模型选择权的根本关切。本文以论小文、91Writing、LiteAI Writer、GEOFlow等具有代表性的开源项目为分析对象，从技术架构分层、一键生成的工程实现、API密钥管理与模型调度、以及宝塔面板部署路径四个维度展开论述。研究发现，当前开源AI写作系统的技术路线呈现明显的分层特征：轻量级PHP方案以“零依赖、单文件配置”为核心卖点，适合个人快速自部署；Vue 3前端项目以“纯前端、数据本地化”为设计原则，将AI能力的选择权完全交还给用户；Python/Tkinter方案则代表了本地化全自动创作的另一种路径。部署实践方面，宝塔面板的普及使PHP方案的部署流程被压缩至“上传源码—导入数据库—配置API密钥”三个核心步骤，而Node.js和Python方案则对服务器的运行时环境提出了更高要求。本文认为，开源AI写作系统的核心价值不在于功能的多寡，而在于“生成逻辑的可审计性”和“部署路径的自主可控”，这两点构成了其与商业AI写作服务之间最本质的差异。

关键词：开源AI写作；一键生成器；API密钥管理；宝塔部署；独立部署

一、引言
AI写作工具的市场格局在2024年至2025年间发生了显著变化。一方面，商业AI写作SaaS服务在功能迭代和模型接入上持续投入；另一方面，一批以“真开源、真免费、可独立部署”为定位的项目在GitHub和Gitee上快速积累了用户。论小文AI论文开源版在项目说明中明确标注“全网最易使用、真免费、真开源”，采用MIT协议，全开源无限制，允许任意二次开发。91Writing以Vue 3 + Element Plus构建，强调“纯前端项目，所有数据均保存在本地，不提供云同步服务”，大模型API全部由用户自行配置。LiteAI Writer则将自己定位为“轻量级、单实例的PHP应用”，以极简依赖和易于部署为核心优势。

这些项目的共同特征值得关注：它们都不约而同地将“API密钥的用户自主配置”作为核心设计原则，而非试图提供统一的AI生成服务。这意味着，用户获取的是一套完整的写作工具框架，而AI能力的来源——调用哪个模型、使用哪个供应商、花费多少成本——完全由用户自行决定。这一设计选择背后的产品哲学是：AI写作工具的“能力”不应与“工具本身”捆绑，用户应当拥有选择和切换AI能力的自由。

本文试图回答以下问题：当前主流开源AI写作系统的技术架构是如何分层的？“一键写作生成器”的产品逻辑在工程层面是如何实现的？API密钥管理和多模型调度的设计思路是什么？以及基于宝塔面板的部署路径包含哪些关键环节？

二、技术架构的分层与路线差异
2.1 PHP生态：极简依赖与快速部署
PHP方案在开源AI写作系统中占据了显著比例，其核心优势在于部署门槛低。论小文采用前后端分离架构，前端使用Uniapp + Vue2，支持PC端、H5端、微信浏览器端和微信小程序端，后端使用PHP 7.4配合ThinkPHP 6.1.0框架，运行环境要求PHP >= 7.4、MySQL >= 5.7。项目目录结构清晰地分为三个部分：lunxiaowen（后端项目代码）、lunxiaowen-uni（前端项目代码）、public（打包后的文件，可直接部署）。

LiteAI Writer代表了另一种PHP设计取向：无框架、原生开发、单文件数据库。其技术栈速查信息显示，后端为PHP 7.4+原生开发，数据库使用SQLite文件数据库，前端为TailwindCSS + 原生JavaScript，AI集成通过DeepSeek API的OpenAI兼容接口完成。项目的核心卖点被明确列为“无需安装复杂依赖，开箱即用”和“单文件数据库，易于备份和迁移”。配置和提示词存储在data/目录下的简单JSON文件中，部署时只需将源码上传到任何支持PHP的服务器即可运行。

GEOFlow同样采用PHP 7.4+原生开发，但定位为“AI驱动的自动化内容生成与发布平台”，主要用于批量生成SEO优化的文章内容。其技术栈包括SQLite数据库和TailwindCSS + 原生JavaScript前端，支持进程级任务管理和监控、批量AI内容生成和完整的后台管理系统。

PHP生态方案的整体特征可以概括为：技术栈成熟、部署路径清晰、对服务器资源要求低，适合个人用户和中小团队快速搭建属于自己的AI写作平台。

2.2 Vue 3前端方案：纯前端与数据本地化
91Writing采用了与PHP方案截然不同的技术路线。该项目基于Vue 3 + Element Plus构建，其产品声明中明确写道：“91写作为纯前端项目，所有数据均保存在本地，不提供云同步服务”“本项目大模型API全部为用户自行配置，不提供公共API服务”“本项目内置提示词均为预设演示，可以配置自己的提示词库来使用”。

这一“纯前端”定位的工程含义是：项目本身不包含任何后端服务器逻辑，所有数据处理和AI调用都在用户的浏览器中完成。数据存储依赖浏览器的本地存储机制，用户的小说项目、章节内容、提示词配置都保存在本地。AI能力的调用通过浏览器直接向用户配置的API端点发起请求，中间不经过任何第三方服务器。

91Writing支持集成GPT、Claude、Gemini、DeepSeek等主流AI模型，采用OpenAI格式API进行统一调用。功能层面覆盖了从构思到成文的全流程：大纲生成与章节管理、智能续写（支持自定义续写方向和200至5000字的字数要求）、AI内容润色（语法、文风、情感、逻辑四个维度）、世界观构建系统、写作目标跟踪和统计分析。项目提供了在线演示地址和视频教程，包括API配置教程和本地部署教程。

这一技术路线的产品价值在于“数据不出本地”——用户的创作内容不会上传到任何服务器，API密钥也保存在浏览器本地，从根本上消除了数据泄露的风险。其代价是用户需要自行解决API密钥的获取和配置问题，且无法在多个设备之间同步创作数据。

2.3 Python/本地模型方案：全自动创作与本地LLM
wyg5208/AI_writing_novel项目代表了一种面向“全自动创作”场景的技术路线。该项目使用Python 3.7+和Tkinter构建桌面应用，结合OLLAMA本地大语言模型，实现从创意生成到自动写作的全流程自动化。其核心功能包括：自动创意生成、智能内容创作、连续创作循环（支持24小时不间断自动创作，一篇接一篇）、自动保存功能（文件名包含字数和时间戳）、实时状态监控和思维推理展示。

这一方案的技术特征在于“本地模型”的选择。用户需要自行安装OLLAMA并拉取支持中文的大语言模型，项目推荐使用huihui_ai/qwen2.5-1m-abliterated:14b。生成的小说保存在generated_novels文件夹中，文件名格式为[字数]字_[时间戳].txt，同时支持导出为DOCX格式。

Python/本地模型方案的优势在于“零API成本”和“完全离线运行”。一旦本地模型部署完成，用户可以无限次调用而不产生任何API费用，且所有数据完全在本地处理。其代价是对硬件资源的要求——运行14B参数量的模型通常需要至少16GB内存和相应的GPU资源，且本地模型的生成质量与云端前沿模型之间存在可感知的差距。

nspox项目则代表了Python生态下更完整的AI写作平台方案。其技术栈包括FastAPI + Python 3.10+后端、React 19 + TypeScript前端，使用PostgreSQL、Redis、MongoDB、MinIO作为基础设施，支持Docker部署。项目定位为“帮助创作者管理作品、章节、素材与协作编辑流程，并通过AI辅助完成分析、续写、润色和创作管理”，开源版本聚焦本地开发、私有化部署和可扩展AI写作工作流。源码基于MIT协议开源，明确允许“学习、研究、二次开发以及商业部署”。

三、一键写作生成器的产品逻辑与工程实现
3.1 三步交互的极简设计
“一键写作生成器”的产品核心是降低操作门槛。论小文的交互流程被压缩为三个步骤：选择科目与输入论文题目→生成论文提纲→生成完整论文。用户只需选择论文品类（毕业论文、期刊论文、开题报告、职称论文），输入标题，系统自动生成大纲，查看大纲后点击生成完整论文，平均用时约1分钟。

这一极简交互的工程实现依赖于“模板化Prompt”的设计。系统将复杂的写作任务拆解为“大纲生成”和“正文生成”两个独立的AI调用阶段。大纲生成阶段的Prompt模板包含论文类型、学科领域和题目信息，正文生成阶段的Prompt模板则在大纲的基础上扩展为完整的学术文本。用户的操作被限制在“选择类型—输入题目—点击生成”的有限步骤中，避免了Prompt工程的学习成本。

3.2 提示词模板管理与用户自定义
LiteAI Writer在“一键生成”的基础上增加了提示词管理的灵活性。用户可以在Web界面中配置API密钥、端点URL、模型名称和系统提示词，同时可以添加、查看和删除自定义提示词模板。自定义模板需要包含{user_input}占位符，生成时用户选择的提示词模板会将输入框中的内容替换到占位符位置，再发送给AI模型。

91Writing的提示词库设计更为系统化。其智能提示词库按“大纲生成、正文创作、润色优化、对话场景”等分类管理，内置了基础正文、对话生成、场景描写、动作情节、心理描写等多种专业模板，并支持变量系统和模板导入功能。提示词的效果追踪功能允许用户查看哪些模板在实际生成中表现更好。

这些设计的共同指向是：一键生成的“便捷性”与提示词管理的“可控性”之间需要平衡。完全固化的Prompt模板虽然操作最简单，但无法适配多样化的写作需求；过于复杂的提示词配置则会增加使用门槛。当前主流方案的做法是提供预设模板作为默认选项，同时开放自定义能力作为进阶功能。

3.3 API密钥管理的安全考量
所有开源AI写作系统都面临同一个工程问题：API密钥如何安全地存储和使用。LiteAI Writer采用了最简单的方式——将API密钥保存在data/目录下的config.json文件中。项目在说明中明确标注了安全警告：“直接在config.json中存储API密钥对这种简单工具来说很方便，但在生产或共享环境中是不安全的。请保护此文件，并考虑使用更安全的方法（如环境变量）”。

91Writing作为纯前端项目，API密钥保存在浏览器本地存储中，不上传到任何服务器。这一设计在“数据安全”层面优于服务器端存储，但用户需要意识到：浏览器本地存储的密钥在共享设备上可能被其他用户访问。

nspox项目的做法更为规范：项目声明中明确要求“提交代码前请确认没有提交.env、真实API key、token、密码”，AI模型供应商由本地环境变量配置，仓库不会提供真实API key。这一实践遵循了“配置与代码分离”的标准安全原则，适合团队协作和公开代码仓库的场景。

四、宝塔面板部署的实践路径
4.1 环境准备与站点创建
宝塔面板是PHP类AI写作系统最主流的部署工具。以论小文为例，部署的第一步是在宝塔面板的软件商店中安装Nginx、MySQL 5.7和PHP 7.4。创建站点时，需要将站点目录设置为源码解压后的根目录，并将运行目录指定为public文件夹。

小狐狸AI系统的部署要求与论小文类似：在宝塔新建站点，PHP版本使用7.4，将后端文件上传到站点根目录，运行目录设置为/public，导入db.sql数据库文件，修改.env配置文件中的数据库连接信息。伪静态规则需适配ThinkPHP框架，安全配置建议开启SSL证书。

4.2 源码上传与数据库配置
源码上传环节需要注意文件权限的配置。PHP项目通常需要将runtime目录、public/uploads目录设置为可写权限，否则系统可能无法正常生成缓存文件或保存上传内容。数据库配置方面，论小文的环境要求为PHP >= 7.4、MySQL >= 5.7，推荐的服务器环境为Nginx + PHP 8.0 + MySQL 5.7。数据库连接信息通常存储在.env文件中，需要根据宝塔中创建的数据库信息进行修改。

4.3 API密钥配置与系统初始化
源码部署完成后，系统通常提供一个安装引导页面或后台管理入口。论小文的初始化流程要求用户“配置apikey（添加客服微信免费获取）”，然后才能进入论文生成环节。LiteAI Writer则直接在Web界面的“API Configuration”部分输入API Key、Endpoint URL和模型名称，点击保存即可。

对于91Writing这类纯前端项目，部署流程有所不同：用户需要克隆仓库到本地，安装Node.js依赖，执行npm run dev启动开发服务器，或执行构建命令生成静态文件后部署到任意静态托管服务。API密钥的配置在Web界面中完成，无需修改任何配置文件。

4.4 Node.js方案的特殊要求
99AI项目基于Node.js构建，支持Docker一键部署，同时也提供了宝塔面板的部署指南。其部署环境要求包括Node版本管理器（推荐Node.js 22.x），需要确保npm、yarn、pnpm、pm2模块完整。宝塔面板中需要安装“Node版本管理器”，将命令行默认Node版本设置为项目要求的版本，然后通过“Node项目”功能添加和管理应用。

Docker部署路径则更为简洁：拉取最新镜像后运行容器即可完成部署。项目说明中建议在受保护的内网环境中部署99AI以确保数据安全。这一建议反映了AI写作系统的一个共性安全考量：API密钥和生成内容都存储在服务器上，暴露在公网环境中需要额外的安全防护措施。

五、结语
开源AI写作系统的核心价值不在于“免费”，而在于“生成逻辑的可审计性”和“部署路径的自主可控”。当用户可以选择调用哪个模型、将数据存储在何处、以何种方式部署系统时，AI写作工具从“黑箱服务”转变为“透明基础设施”。这一转变对于学术写作、商业文案和小说创作等对内容隐私和生成质量有特定要求的场景，具有实质性的意义。

技术选型方面，PHP方案适合追求快速部署和低运维成本个人用户，Vue 3纯前端方案适合对数据隐私有高要求的创作者，Python/本地模型方案则为“零API成本”和“完全离线”提供了可行路径。无论选择哪条路线，“API密钥的用户自主配置”和“生成内容的数据主权”都应当作为评估的第一原则。开源方案提供的不仅是一套可运行的代码，更是一种“用户掌控AI能力”的产品哲学。
